# 抖音商城用户行为数据分析 · 第 3 周工作计划

- **项目名称**: 抖音商城用户行为数据分析
- **执行周期**: 第 3 周 (周一 ~ 周五)
- **代码仓库**: https://github.com/xueyingli450-svg/tiktok_user_analysis
- **核心目标**: 基于第二周产出的 34 维全维度特征大宽表，构建“用户未来 7 天是否购买”的二分类预测任务；完成样本时间窗口切分与类别不平衡处理；训练并调优逻辑回归、XGBoost、LightGBM 传统模型及阿里 DIN 深度兴趣网络；通过 Stacking 集成融合与 SHAP 归因分析，输出高性能预测模型与业务可解释性结论。

---

## 一、 逐日具体工作安排

### 【周一】样本集构建、标签定义与数据集划分
1. **时间窗口划分与打标**: 严格划分特征观测窗口（前 24 天）与标签预测窗口（后 7 天），提取用户在未来 7 天内是否产生真实购买行为，生成二分类目标标签（1=购买, 0=未购买）；
2. **分层数据集切分**: 采用分层抽样（Stratified Split）按照 70% 训练集、10% 验证集、20% 测试集划分样本，确保各数据集正负样本比例分布一致；
3. **样本平衡策略**: 分析正负样本比例，采用类别权重（Scale Pos Weight / Class Weight）策略应对电商购买样本稀疏问题。

### 【周二】传统分类基准模型搭建与多指标评估
1. **多模型基准训练**: 构建并训练三种经典分类器：逻辑回归（Logistic Regression）、XGBoost 与 LightGBM；
2. **模型综合性能对比**: 在测试集上评估对比 AUC、准确率（Accuracy）、精确率（Precision）、召回率（Recall）及 F1-Score；
3. **绘制性能评估曲线**: 绘制三种模型的 ROC 评估曲线对比图（保存为 `docs/figures/fig10_model_roc_curves.png`）。

### 【周三】Optuna 自动化超参数调优
1. **贝叶斯超参数搜索**: 使用 Optuna 调参框架，以验证集 AUC 为优化目标，对 LightGBM 和 XGBoost 的核心参数（树深度 `max_depth`、学习率 `learning_rate`、叶子数 `num_leaves`、正则化项 `reg_alpha/reg_lambda`）进行 50 轮贝叶斯搜索；
2. **最优模型锁定与对比**: 导出最优参数组合，对比调参前后的测试集 AUC 提升幅度，锁定表现最佳的单模型。

### 【周四】深度学习 DIN 序列模型与 Stacking 模型融合
1. **DIN 序列模型搭建**: 搭建包含 Embedding 嵌入层、局部注意力机制（Local Activation Unit）与全连接分类层的 DIN 神经网络，组织用户历史点击序列输入；
2. **Stacking 模型融合方案**: 以 LightGBM、XGBoost 和 DIN 作为初级基学习器，逻辑回归作为元学习器进行预测概率融合，探索多模型集成带来的性能增益。

### 【周五】SHAP 模型可解释性分析与周报汇总
1. **SHAP 特征归因分析**: 计算最佳模型的 SHAP 值，绘制全局特征重要性摘要图（保存为 `docs/figures/fig11_shap_summary.png`），识别影响用户购买决策的关键驱动特征；
2. **模拟 A/B 测试方案设计**: 基于模型预测的购买概率分值，设计推荐系统的模拟 A/B 测试方案；
3. **成果汇总与周报提交**: 整理全部算法代码至 `src/models/` 目录，编写并提交第三周工作周报。

## 三、 本周技术难点与应对准备

1. **时序数据穿越（Data Leakage）防范**:
   - *应对方案*: 严格按照时间先后顺序切分特征窗口（前 24 天）与标签窗口（后 7 天），绝不使用未来时间段的任何信息，保证模型评估的真实性。
2. **DIN 序列输入的长度对齐**:
   - *应对方案*: 针对不同用户点击长度不一的问题，设置固定序列截断长度（如最近 20 次点击），不足部分进行补零填充（Padding），保证批次计算高效稳定。
